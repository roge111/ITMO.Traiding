# ADR-001: Разделение хранилищ — ClickHouse и PostgreSQL

#docs #adr #database

**Статус:** Принято  
**Дата:** 2024  
**Участники:** Команда ITMO.Trading

---

## Контекст

Система ITMO.Trading хранит два принципиально разных типа данных:

1. **Котировки** — высокочастотные временные ряды. Генерируются ядром каждые 3 секунды, записываются Go-инжестором каждую секунду. Требуют быстрой агрегации, диапазонных запросов по времени, хранения истории.

2. **Пользовательские данные** — транзакционные CRUD-операции. Регистрация, авторизация, портфель, операции торговли. Требуют ACID-транзакций (баланс + портфель должны обновляться атомарно).

## Проблема

Нужно выбрать: использовать одну БД или две специализированные?

## Рассмотренные варианты

### Вариант A: Только PostgreSQL
- **+** Одна БД, проще инфраструктура
- **+** Полные ACID-транзакции для всего
- **−** PostgreSQL плохо масштабируется для time-series данных высокой частоты
- **−** INSERT-heavy нагрузка от котировок конкурирует с транзакциями пользователей

### Вариант B: Только ClickHouse
- **+** Отличная производительность на аналитических запросах и time-series
- **−** ClickHouse не поддерживает полноценные ACID-транзакции
- **−** Нет JOIN между таблицами с высокой частотой мутаций
- **−** UPDATE/DELETE работают иначе (асинхронно), непригодны для баланса

### Вариант C: ClickHouse для котировок + PostgreSQL для пользователей ✓
- **+** Каждая БД используется по своему назначению
- **+** ClickHouse: быстрые аналитические запросы, time-series, история цен
- **+** PostgreSQL: ACID-транзакции для баланса и торговых операций
- **−** Более сложная инфраструктура (два сервиса в docker-compose)
- **−** Нет cross-database JOIN (но бизнес-логика не требует его)

## Решение

**Принят вариант C.** ClickHouse хранит `quotes` и `quotes_history`. PostgreSQL хранит `users`, `portfolio`, `trades`.

## Последствия

**Положительные:**
- Gateway читает котировки из ClickHouse через JDBC HTTP (port 8123) и пользовательские данные из PostgreSQL через JDBC (port 5432) — оба быстро
- Go-инжестор пишет только в ClickHouse через native protocol (port 9000) — оптимальная производительность
- ACID-транзакции в PostgreSQL обеспечивают корректность торговых операций

**Отрицательные / технический долг:**
- `DataBaseManager` и `TradingRepository` создают соединения через `DriverManager` без пула — узкое место при высокой нагрузке (задокументировано в [[../modules/gateway]])
- Синхронизация данных между БД не нужна бизнес-логически, но усложняет тестирование
